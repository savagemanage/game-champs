# Arena Champions — a League-inspired single-lane arena game (v1)

A from-scratch React 18 + TypeScript + Vite 5 + Phaser 3 web game: champion select into a single-lane arena where a player champion, AI rival, minion waves, turrets, and nexuses fight until one nexus falls. The combat and AI math live in Phaser-free, unit-tested modules; Phaser only renders and feeds plain data through them. The app is fully bilingual (Korean + English) with a persisted toggle and a parity-tested locale set, ships zero binary assets (CSS-art portraits, shape-based VFX, procedural WebAudio SFX), and is wired for GitHub Pages under `/game-champs/`. Build, typecheck, and 69/69 tests are green.

Watch for: turrets fire at roughly double their intended rate because `attackCdRemaining` is decremented twice per frame (confirmed); the enemy nexus has no turret-gating so a champion can attack it while the enemy turret still stands (confirmed); an enemy Dawnsong can never deal ability damage and heals only itself, making that matchup a near-non-threat (confirmed); and first-time visitors on a non-Korean browser load in English despite the "mandatory Korean" requirement (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The architecture is the strongest part of this change. Combat math (`combat.ts`) and bot decisions (`ai.ts`) are deliberately Phaser-free and exhaustively unit-tested; the Phaser scene owns sprites and pushes plain data through the shared helpers, and a tiny external store bridges scene state to a React HUD via `useSyncExternalStore` without React ever re-rendering Phaser. The React↔Phaser lifecycle is guarded against StrictMode double-mount, and a `matchNonce` forces a fresh scene even on an identical-champion rematch.

The simulation's correctness gaps live in the untested scene glue, not the pure logic. Turret cooldowns tick twice per frame, so turrets shoot about twice as fast as configured. Targeting is pure nearest-enemy with no structure priority, so the nexus is attackable through a standing turret — a departure from the MOBA model the game imitates.

The AI has a structural blind spot around non-damaging abilities: casting is gated on an enemy being inside the ability's range, which is correct for offensive skills but wrong for self-heals and self-buffs. Combined with heal/buff abilities that only ever affect the caster, an enemy enchanter (Dawnsong) becomes almost harmless — it can neither threaten the player with abilities nor damage the nexus with them.

The i18n surface is complete and parity-tested, and the language choice persists. The one requirement question is defaulting — Korean is fully present but not forced as the initial language for a fresh non-Korean visitor.

Deployment is correctly configured for a project page: `base: '/game-champs/'`, a matching absolute favicon path, and a standard Pages Actions workflow.

<summary>Issues (7)</summary>

1. **Turret double cooldown tick** — `attackCdRemaining` is decremented in both `regenAndTick` (all entities) and `updateTurret`, so turrets fire at ~2× their configured attack speed. Remove the decrement from `updateTurret`.
2. **Nexus not gated by turret** — nearest-enemy targeting lets champions and minions hit the enemy nexus while its turret still stands; add structure/turret targeting priority (or nexus invulnerability while the turret lives) to match the intended MOBA flow.
3. **AI never uses defensive abilities correctly** — `canCast` requires an enemy within the ability's range, so self-heals/self-buffs only fire when an enemy is close. Gate non-offensive abilities on self-state (low hp) rather than target range.
4. **Enemy enchanter is a non-threat** — Dawnsong's heal/buff abilities carry `damage:0` and heals apply to the caster, so an enemy Dawnsong can neither damage the player via abilities nor push the nexus with them. Give it a way to threaten, or exclude pure-support kits from the enemy pool.
5. **Korean not the default for new visitors** — detection order `['localStorage','navigator']` + `fallbackLng:'en'` means a fresh non-Korean browser loads English. If Korean is mandatory as the default, set `lng`/`fallbackLng` to `ko` or reorder detection.
6. **Nearest-enemy tie resolution** — `nearestEnemy` uses `<=`, so equidistant targets resolve to the last unit scanned, which can cause target flicker between overlapping minions. Use `<` if deterministic nearest is wanted.
7. **HP-regen order lets a lethal blow be softened** — champion hp regen in `regenAndTick` runs on the same frame damage lands, so a champion at a sliver ticks back up before the next hit. Low impact, worth confirming intended.

<summary>Details</summary>

### Turret cooldowns tick twice per frame

`update()` calls `updateTurret(...)` and then `regenAndTick(dt)`. `regenAndTick` loops every entity and decrements `attackCdRemaining` when positive:

```ts
for (const e of this.allEntities) {
  if (e.stunned > 0) e.stunned = Math.max(0, e.stunned - dt);
  if (e.unit.attackCdRemaining > 0) {
    e.unit.attackCdRemaining = Math.max(0, e.unit.attackCdRemaining - dt);
  }
}
```

But `updateTurret` also decrements the same field:

```ts
if (u.attackCdRemaining > 0) {
  u.attackCdRemaining = Math.max(0, u.attackCdRemaining - dt);
}
```

Turrets lose `2·dt` of cooldown per frame and fire at roughly double `TURRET_ATTACK_SPEED`. Champions and minions decrement only in `regenAndTick`, so this asymmetry is turret-specific (confirmed). Dropping the decrement inside `updateTurret` matches how every other unit is handled.

### Nexus is reachable through a standing turret

Targeting everywhere is `nearestEnemy(u, this.livingUnits(), range)`, which considers all enemy unit kinds equally — minion, champion, turret, nexus. There is no rule that the turret must fall before the nexus can be damaged, and no turret aggro-shield for diving. A player (or a pushing minion wave) that slips past the turret's position can attack the enemy nexus directly while the turret still stands (confirmed). For a game explicitly modeled on the LoL lane, turret-then-nexus gating is a core expectation; without it the "push" loop collapses into "walk to the nexus." Adding structure targeting priority — or making the nexus invulnerable while its turret lives — restores the intended objective flow.

### AI can't use defensive abilities, and the enchanter kit can't threaten

`canCast` treats every ability the same way: ready, affordable, and `distanceToTarget <= abilityRanges[slot]`. For offensive skills that's right. For a self-heal or self-buff it's backwards — those don't need an enemy in range, yet the bot will only fire them when an enemy is close, the opposite of when you want to heal or shield up (confirmed via the shared gate in `ai.ts`).

This compounds with the enchanter's data. Dawnsong's W/E/R are `heal`/`buff` with `damage: 0`, and in `castAbility` heals apply to `caster.unit`. So an enemy Dawnsong never damages the player with abilities, never damages the nexus with abilities, and heals only itself — and even that self-heal is gated on an enemy being within 700–900 units. The Dawnsong matchup, as the opponent, is dramatically less threatening than any other and can barely close out a game. Either give non-offensive kits a way to matter on the enemy side (target allies/self on self-state), or keep pure-support champions out of the enemy pool.

### i18n completeness and the default-language question

Every rendered string — screens, HUD, ability names and tooltips, roles, stats, behavior tags, settings, champion lore — resolves through a key, and `i18n.test.ts` enforces identical key sets across `ko` and `en` so a missing translation fails CI. The Korean copy uses idiomatic MOBA terminology (원거리 딜러, 스킬샷, 넥서스), and the toggle persists through the LanguageDetector `localStorage` cache under `lol-lang`.

The open question is the default. Detection order is `['localStorage','navigator']` with `fallbackLng: 'en'` and no explicit `lng`, so a first-time visitor with a non-Korean browser loads English, not Korean (likely). If "mandatory Korean" means the UI must be *available* in Korean, this is satisfied; if it means Korean should be the initial experience, the config needs `lng: 'ko'` or `fallbackLng: 'ko'` (or `navigator` removed / reordered). Worth confirming intent before shipping.

### Minor simulation notes

`nearestEnemy` compares with `<=`, so among equidistant candidates the last one scanned wins; with stacked minions this can flip a unit's target frame to frame. Switching to `<` gives a stable nearest (possible, low impact).

Champion hp regen runs in `regenAndTick` on the same frame damage lands, so regen slightly blunts burst and a champion at very low hp can tick back up before the next incoming hit. Confirm this ordering is intended (possible).

### The one non-obvious lifecycle decision

`PhaserGame` includes `matchNonce` in the effect deps alongside the champion ids. Champion-id-only deps would silently skip scene recreation on a same-champion rematch; the nonce is what forces a fresh scene there, and `onGameEnd` is read through a ref so a changing callback doesn't tear the game down.

### Test coverage

The pure logic is well covered: armor mitigation (including negative armor), lethal/heal clamping, cooldown ticking and progress, every ability `behavior` mapping, and the full AI priority tree including retreat-vs-execute, affordability, and range fallbacks. Champion-data tests guard i18n-key resolution in both locales; the audio engine's headless no-op path is tested; `ChampionSelect`/`App` cover selection and language switching.

Not tested (and where the confirmed bugs live): everything inside `BattleScene`. The turret double-tick, nexus targeting, respawn timer, wave spawning, and cast application are scene-only and have no coverage — the scene's untestability is the direct reason these slipped through. The unit data is already Phaser-free, so extracting a headless "tick the simulation by dt" step would let turret cadence, targeting priority, and the win condition be asserted without a canvas.
