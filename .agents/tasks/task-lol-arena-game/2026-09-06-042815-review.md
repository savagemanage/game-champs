# Arena Champions — v1 fix verification (v2)

Second review pass over the League-inspired single-lane arena game. The v1 pass returned NEEDS_CHANGES with seven items; a coder has since reworked the combat/AI math and i18n config and added a targeting test suite (test count rose from 69 to 91). This pass verifies each fix against the code, checks that the new pure helpers are correct and that their tests would fail if reverted, that the Phaser scene actually routes through the new gating with no bypass, and that nothing regressed. Six code fixes hold up; the seventh (HP-regen ordering) was consciously deferred.

Watch for: nothing blocking. The turret double-tick, nexus turret-gating, AI self-sustain gating, enemy-enchanter threat, and Korean default are all genuinely fixed and covered by tests that pin the behavior (confirmed). The only residual is the deferred HP-regen-on-damage-frame ordering, a continuous MOBA-style choice rather than a bug (confirmed).

**Verdict**: APPROVED

## High-level view

The cooldown tick is now single-sourced: `advanceAttackCooldown`/`canBasicAttack`/`resetAttackCooldown` live in the pure `combat.ts`, the scene decrements every unit exactly once per frame in `regenAndTick`, and `updateTurret` no longer touches the cooldown — the double-decrement that made turrets fire at ~2× is gone.

Nexus targeting is now structure-gated. A pure `StructureLine` model plus `isTargetable`/`nearestTargetableEnemy` skip a nexus while its guarding turret lives, and every combatant in the scene targets through a single `findTarget` wrapper. The free `nearestEnemy` is no longer called anywhere in production code, so no path reaches the base through a standing turret.

The AI splits casting by behavior: heals and buffs are gated on self-state (hurt at or below 0.85 hp) with no range requirement and tried before lane-walking, while offensive abilities keep range gating. Combined with Dawnsong's Q now being a real 75-damage skillshot, an enemy enchanter both sustains itself and threatens the player — the old non-threat matchup is resolved.

Korean is now the enforced default: `fallbackLng` is `ko` and `navigator` was dropped from the detection order, so a fresh non-Korean visitor loads Korean; because `localStorage` is still read first and cached, an explicit toggle choice persists and wins on the next visit.

Nearest-enemy tie resolution is now deterministic (first-scanned among equidistant), removing target flicker. HP regen still runs on the damage frame — the coder deferred reordering it as continuous regen where a lethal blow still kills on its own frame.

<summary>Details</summary>

### Turret double-tick: single-sourced cooldown

`advanceAttackCooldown` is the only place `attackCdRemaining` is decremented, and `regenAndTick` calls it once per entity per frame including turrets. `updateTurret` fires on `canBasicAttack(u)` and calls `resetAttackCooldown(u)` but no longer decrements. The regression is pinned by a test that models the scene loop and asserts one decrement/frame yields the configured cadence while two decrements/frame fire strictly more often; re-adding a second decrement would flip that assertion (confirmed).

### Nexus gating: no bypass path remains

`isTargetable` returns false for a nexus whose guarding turret id is still in the living set, and `nearestTargetableEnemy` filters to targetable enemies before choosing, with a `preferStructures` mode that commits a unit standing on the objective to turret-then-nexus. The scene wires this through one `findTarget` wrapper used by the player auto-attack, the enemy champion, the minions, and the turret. A workspace-wide search confirms `nearestEnemy` has zero call sites outside tests, so there is no lingering ungated targeting — the base cannot be hit through a live turret. The win condition reads `enemyNexus.unit.dead`, which can only be set once the nexus takes damage, now prevented until the turret falls (confirmed). `targeting.test.ts` covers the shielded/unshielded nexus, structure preference, plain-nearest fallback, and maxRange, and would fail if the gate were removed (confirmed).

### AI casting split: self-sustain vs offensive

`canCast` branches on `isNonOffensive`: heal/buff require only that the bot be at or below `SELF_SUSTAIN_HP_THRESHOLD` (0.85), with no target-range check; offensive abilities keep the ready+affordable+in-range gate. `decideAction` tries non-offensive casts first, so a hurt bot heals before walking the lane, and the scene aims heal/buff casts at the caster's own position rather than the target. The boundary is pinned by tests at exactly the threshold and one tick above it, plus a "heals with no target in range" case and a "still retreats at critical hp when heal is on cooldown" case — the suite would fail under the old range-gated logic (confirmed).

### Enemy enchanter can threaten

Dawnsong's Q is a `skillshot` with `damage: 75` at range 950, while W/E/R are heal/buff on self. An enemy Dawnsong sustains via self-heals gated on its own hp and deals ability damage through Q, so the matchup is no longer harmless. A test mirrors the kit (offensive Q, self-heal R at highest cast priority) and asserts the bot self-heals when hurt with no target — confirming both halves of the fix (confirmed).

### Korean default with working persistence

`fallbackLng: 'ko'` and detection `order: ['localStorage']` (navigator removed) mean a first-time non-Korean visitor loads Korean. `caches: ['localStorage']` under `lol-lang` is intact and `LanguageToggle` calls `i18n.changeLanguage`, which writes that cache — so an explicit choice persists and, being read first, wins over the default on the next load. The parity test still enforces identical ko/en key sets, and a new test asserts `fallbackLng` contains `ko` and that `app.title` resolves to the Korean string, so a revert to an `en` default would fail CI (confirmed).

### Deterministic nearest tie-break

`nearestEnemy` seeds `bestDist` from `maxRange` and only replaces `best` on a strictly-closer candidate (first-scanned wins among equidistant), and `nearestTargetableEnemy`'s per-kind scan uses `<` as well. A test asserts the first of two co-located units is returned regardless of scan order, so the flicker-prone `<=` behavior would fail it (confirmed).
